## 发现并处理的问题

1. 未保存稿件与已保存稿件菜单的条目位置可能不同。最初复用坐标误触另存，留下额外空白合成稿；已记录，未重复导入或删除。打开菜单后必须重新观察具体条目，不能沿用旧坐标。
2. 滚动后旧坐标曾把标题输入到测试落款区。结果检查发现后已恢复。新增 `focus` 用唯一 CSS 控件执行 WebDriver 点击、自动滚动，并核对活跃元素确为目标；只在成功后继续选择和输入。
3. Backspace 首次把空组件合并到落款，后续一次删掉相邻测试字符。已完整恢复落款，再通过明确删除入口补测。不能写成按若干次 Backspace 的通用删除流程。
4. 编辑器快速输入占位不在文章预览正文内。只含嵌套 span 的段落也可能有内容；判断空段必须使用完整渲染文本。

## 可接续的方法

先核对稿件身份、当前版本及目标内容，再对输入框或完整文本块定位。输入前用 `focus`；成功后执行 `SelectAll` 和 `type`，随后核对实际结果。合成稿落款块仅含两行已知测试文字，整块替换不代表含多种行内样式的复杂落款也已验证。

空段落需要区分文本块内的空段与独立空组件。本轮通过的是顶层独立空文本组件：确认其全文为空且无图片后，定位并选中该组件，从当前工具栏删除，立即检查其他文字与素材。含嵌入内容、隐藏媒体、链接、嵌套组或复杂装饰的表面空组件不能套用这项结果。

每次结构改动后重新读取节点和工具栏。`inspect` 新增的节点 CSS 路径只反映当次 DOM，不能作为永久稿件或组件 ID。`focus` 只验证唯一性与焦点，不代替稿件身份、目标内容或执行者租约检查。当前 `focus` 用于顶层编辑控件，不能直接重用 iframe 内节点路径。

保存后从已记录稿件入口重开、刷新，等待预览非空且连续稳定，再检查分隔符、尾部空段与内容保留；动作执行成功不能代替保存后的验收。
