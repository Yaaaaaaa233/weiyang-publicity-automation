# Mac 手动触发与公众号预览试部署

更新：2026-10-14。使用者指定先在 Mac 部署测试，减少 Windows 远程调试；目标团队企业微信账号仅允许 Windows 客户端登录。

后续进展：使用者选择沿用 DSH 桌面登录；已新增原生桌面插件、投递账本及有限接续接口，配置仍保持不执行真实业务。最新部署、测试和阻断状态以 [桌面接续说明](manual-trigger-desktop.md) 为准；下文 queue_only 段记录的是首轮试部署，不代表后续能力已完成真实验收。

## 部署边界

企业微信客户端用于创建、管理机器人。Mac 上的接收程序通过 Bot ID 与 Secret 主动建立 WebSocket 长连接，无需企业微信 Mac 客户端登录或公网回调端口。创建入口与团队是否开放此能力仍需在 Windows 实际核对；原通知 Webhook 不能当作智能机器人凭据。

本轮 Mac 是独立功能试验节点。Windows 仍是既有正式业务执行者。当前接收入口仅有 `queue_only` 模式，不启动 agent、不读写预约、不编辑稿件、不提交公众号同步。尚未验证群消息真实到达、agent 接续或公众号预览发送。不能把离线测试成功描述为完整业务已接通。

公众号预览是新增的授权目标：由使用者登录网页，核对本轮草稿组合后，测试向使用者指定的唯一微信号发送预览。接收人身份保存在本机私有配置，不硬编码公开仓库；不发布或群发。

## 已落地内容

- `integrations/wecom-control/receiver.mjs`：企业微信官方 SDK 1.0.7 长连接接收器；固定指令转交本地策略接口，不把群文字作为 agent 提示词或 shell 命令。
- `scripts/wecom_control.py`：指定机器人、群和成员校验；仅接受“连接测试”“补跑今天”“查询进度”，正文引用不触发；实际时钟确定上海业务日期；若事件包含产生时间，拒绝超过五分钟或未来时间。
- 私有 SQLite 测试队列：按机器人及消息 ID 去重，新的补跑消息遇到已有待处理请求则返回忙；队列记录不等于启动或完成业务。无名单或凭据则不能接通。
- 连接状态留 `local/wecom-control-test/connection.json`，不打印 SDK 原始参数、凭据或消息。回复结果未知不自动重发；平台回执不能推断成员已读。
- 本机官方 npm 安装完成，SDK 导入与接口存在性检查通过；10 项新离线测试通过，全套 337 项通过。

## 配置与运行

将 `fixtures/wecom-control.example.json` 复制到 `local/wecom-control-test/config.json`，填写真实 Bot ID、机器人展示名以及经核对的群、触发者 ID。示例保持空名单，不能拿它启动真实接收。

机器人 Secret 使用本机私有环境变量 `WECOM_CONTROL_SECRET`。不要在聊天、命令行参数、仓库、截图或公开日志中提供凭据；本轮尚未取得或保存新机器人凭据。Windows 创建后如需迁移凭据，必须使用私有文件传输，并核对具体保存位置和授权范围。

在 `integrations/wecom-control` 中安装及启动：

```sh
npm ci --ignore-scripts
node receiver.mjs
```

`WEIYANG_PYTHON` 指定现有 Python 可执行程序；Mac 默认 `python3`，Windows 可设为 `py`。迁移时保留私有测试队列；不能同时在两台电脑用同一机器人凭据接收。当前不安装开机服务或改定时任务。

## 验收顺序及未完成项

1. Windows 中核对智能机器人 API / 长连接入口，创建一个测试机器人加入指定运营群。机器人凭据创建按操作时确认要求处理。
2. Mac 用其凭据连接；授权成员发送“连接测试”，核对实际接收、回复及去重。群和成员 ID 必须来自真实平台观察，不用昵称猜测。当前尚未封装首次绑定入口，不应为了取 ID 对任意群开放执行权限。
3. 接入固定业务执行器。它需唤醒/启动 agent，在身份与格式检查点持续接续；单次调用 `full_run.py` 不代表完整执行。与 Windows 正式执行、定时任务实行单节点互斥，保留原稿、副本与转存账本；补跑用新 run 实读，已同步组合不重提交，组合变更另行处理。
4. 公众号网页登录后，先定位一份已知草稿组合，核对标题、篇数、顺序、账号和正文，再单次发送指定微信号预览，由使用者确认实际收到。网页入口、接收条件和稳定选择器尚待真实验收，当前没有公众号预览脚本。
5. 单独保存预览账本：草稿身份、版本、接收人、发送预留和结果。预览失败只补预览；未知结果不重发、不重跑秀米同步。最后再把预览及结果通知接入完整流程。

## Mac 浏览器准备记录

本轮启动已有 Mac 浏览器容器，未重建、未改端口或清理命名卷。工具脚本已热替换为仓库版本并核对指纹一致。首次启动 Chromium 失败，实际诊断确认三个 Singleton 符号链接指向旧容器、无 Chromium 进程及业务租约；重新核对后只移除三个失效链接，浏览器随后启动成功，账号数据保留。公众号登录窗口及实际观察记录留 `local/mac-control-preview-20261014/`，不提交 Git。
