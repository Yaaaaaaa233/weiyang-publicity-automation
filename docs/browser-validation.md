# 专用浏览器验证记录

日期：2026-10-01。执行设备：Apple 芯片 Mac，macOS 26.6.2。

## 结论

本机专用浏览器基础能力可行。统一命令接口、中文输入、坐标点击、文字读取、截图取回、会话复用及容器重启后的 localStorage 保留已通过实际测试。使用者已在人工入口完成秀米登录，后续命令复用原会话，截图确认首页显示账号头像。

合成测试稿的输入、读取、保存、预览、图片模板保存后刷新核对及登录后容器重启恢复也已通过本机验证，见[基础稿件验证](article-validation.md)。这些结果不代表正式转存流程、任意复杂稿件检查、跨 agent 业务接管、Windows 部署、异机数据恢复或定时无人值守已经通过。

## 实际环境

- 基础镜像：`selenium/standalone-chromium:4.48.0-20260905`，官方 Docker Hub 与 GHCR 镜像源。
- 镜像清单包含 `linux/arm64` 与 `linux/amd64`；本机实际构建和运行的是 `linux/arm64`。
- 本机运行镜像：`weiyang-publicity-browser:latest`，运行用户 `seluser`。
- Chromium：152.0.7977.75。
- Compose 服务健康；宿主机端口仅为 `127.0.0.1:7900`。WebDriver 未映射到宿主机。
- 浏览器数据与容器截图使用独立命名卷；截图通过桥接程序取回本机 `artifacts/`。

最初的重启测试保留浏览器 localStorage 标记；登录后又验证了重启容器、保留登录并从本机 JSON 定位找回测试稿。本地账本的独立验收另见 `docs/tasks.md`。尚未提供自动任务恢复，也没有测试跨设备登录状态。

## 证据与下载处理

本机证据：`artifacts/browser-check.png`、`artifacts/browser-restored.png`、`artifacts/xiumi-login.png`、`artifacts/xiumi-authenticated.png`、`local/browser-login-view.png`。这些文件由 Git 忽略；登录后的截图包含账号信息，仅留在本机。

普通 Docker 镜像拉取反复停顿，实际采用官方公开镜像的分段下载补齐并导入。全部压缩镜像层 SHA256 与官方清单一致，全部解压层 SHA256 与镜像配置的 `rootfs.diff_ids` 一致。没有关闭 TLS 证书验证，也没有更改系统代理设置。

源码、通用配置和验证说明通过 Git 管理；运行证据、登录数据和本机配置不进入仓库。下载临时文件位于系统临时目录，不进入仓库。
