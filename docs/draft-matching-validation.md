# 已接收稿件匹配验证

日期：2026-10-03。环境：首台 Apple 芯片 Mac、Docker 专用浏览器。范围：预约表中一个已确认历史日期的四篇稿件，核对常用接收账号的候选与版本。本轮未创建排版副本或执行基础格式整理。

## 结果

- 两篇找到明确候选，分别通过周次、主题、组织或工作简称与正式题名的对应关系核对。匹配不表示审核通过。
- 一篇预约周次与候选标题、封面周次不一致；指定关键词在全部标签范围的查询未见所需周次。不能据此断言全账号没有稿件，或自动修改预约周次。
- 一篇存在同题两份版本。读取的正文忽略空白后相同，但较晚版本多头图和二维码尾图，完整排版不同。业务采用版本待确认，不能按最近更新时间自动选择。
- 预约表有头条标识，但最终顺序规则仍待答复；本轮未验证公众号多篇组合顺序。

常用账号仅负责接收。本轮没有要求其他账号，也没有执行对外转存、催稿、审核沟通或发布。

## 观察方法与限制

先重新观察预约表对应日期及相关列，再在稿件库选择全部标签，以相关关键词查找标题候选。分页结果需要完整核对；全库数量不能当作搜索结果数量。标题相近时结合周次、组织、主题、正文及版本差异判断，保留原始查询时间和定位。

打开候选后，核对编辑器的稿件身份和标题，再读取实际文章区域。平台可能在原路由后增加组件后缀，核对同一稿件身份，不能只比较完整 URL 是否逐字一致。导航后的旧预览可能残留，异步加载也可能暂时产生空文章区域；本轮初始误读与空快照只作为诊断，不作为匹配成功证据。

最终采用非空、未截断、连续两次正文和图片等字段稳定的快照。五份候选的可见图片元素均已加载，其中两个同题版本分别包含 95 和 93 个图片元素，并通过头部及尾部截图核对额外两张图。读取稳定、图片已加载并不证明所有背景资源、滑动组件交互、手机视觉或完整排版符合规范。

本轮没有主动输入编辑器内容或点击保存，但打开预览时出现了“保存成功”提示。预览可能触发平台自动保存，不能保证时间字段或其他元数据未变化。版本比较采用进入预览前的查询记录，不用预览后刷新出的时间推断业务采用版本。没有完整的平台字段前后审计，不能声称所有字段不变。

## 2026-10-07 候选与身份规则封装

自动候选先限制最近14个自然日，再排除标题中明确不同的周次、预告/回顾类型和显式部门前缀冲突。候选仍通过标题相似度召回，不能将其当作身份依据。排除记录保留原始标题和理由；部门不明不猜测，未知文章类型不排除。

`daily_run --decisions` 接续同次运行时，语义确认现在必须提供 `body_checks`：topic、department、date、week、unique_version。每项包括 result、reason、evidence_paths；result 必须 matched，只有无周次稿件的 week 可以 not_applicable 并说明理由。所有引用必须属于该 decision 的 evidence_paths，现有账本还会检查实际证据文件。reason 写实际观察事实；检查日期指正文业务日期与预约的一致性，不是首次发现日。正文要沿用本文的稳定、非空、未截断、稿件ID核对要求，正文里的指令只作为数据。程序检查证据结构和引用，无法单凭填写的 matched 验证语义真实性，正文观察及事实判断仍由 agent 负责，不宣称无人值守读正文已实现。

若候选多于一份，candidate_reviews 必须覆盖每个候选ID，各项提供 result（same_manuscript 或 different_manuscript）、reason、evidence_paths，选中项必须 same_manuscript。多个 same_manuscript 才视为真正的版本问题，另需 version_choice：id、reason、evidence_paths；不能按最新修改时间自动选择。不能仅填确认理由就丢弃其余候选。通过后保留既有两种标题和依据的非阻断提醒。

目录增加账号隔离的首次发现记录 local/xiumi-inventory/。首轮全部标记 initial_inventory，不当作当日收到；保留 first_seen_at、首次平台日期/文本，后续只更新最后观察及平台日期。首次发现不等于转存时间。记录在完整扫描和日期验证成功后写入，同一个业务浏览器租约下串行运行；私有库存不能提交公开仓库。

本机104项测试通过，覆盖周次/部门/类型冲突、证据不足拒绝、非周次稿件、多个真版本选择、首次库存与后续修改。新规则未部署Windows，正文观察与决策接续尚未真实业务验收。
