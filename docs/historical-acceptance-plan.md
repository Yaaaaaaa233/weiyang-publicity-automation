# 历史验收模式实施方案

制定日期：2026-10-14。状态：方案已制定，尚未实现或验收；使用者随后决定暂不添加历史模式，当前暂停，优先验收当天正常流程。

## 目标与边界

在真实执行时间重新读取一个已过去、稿件齐全的预约日期，使用与正式流程相同的读表、匹配、副本、排版、组合、同步和通知能力，完成后半段验收。首轮目标为 2026-10-13；执行日期取实际日期，不写死为 10 月 14 日。

这是一种显式运行模式，不是修改系统时间、修改旧观察时间或放宽正式流程。正常模式仍只处理当天。历史验收通过证明业务执行与接续能力，不证明当天业务完成、定时触发或七环全部从零运行成功。

Windows 继续是唯一业务执行者，项目根为 `D:\Study\weiyang-publicity-automation`。Mac 负责修复和交付。沿用现有容器、登录和私有账本；不启用“转存好”标签、不操作公众号后台、不群发、不改调度。

## 1. 统一日期上下文

完整入口拟新增 `--date YYYY-MM-DD` 与 `--historical-test`，同时贯通独立检查入口。参数只是拟定接口，实现前不能作为已可执行命令交付。

- 不指定日期：默认当天正常运行，现有日常提示词不变。
- 指定过去日期：必须同时有 `--historical-test`；历史模式只允许早于执行当天的日期。
- 未来日期、历史模式指定当天、普通模式指定过去日期均拒绝。
- 历史模式默认预览；真实编辑、同步和通知仍由现有 `--execute` 控制，不能因为历史标识自动提交。

采用统一上下文：`date` 保持业务日期（兼容现有字段），新增 `mode`、`execution_started_at`、`execution_date`；观察继续使用真实 `observed_at`，报告的 `run_date` 为报告实际生成日。业务日期、模式和配置签名绑定稳定 `run_id`，不能在接续时改换。

恢复已提交同步可以只读核对结果及接续通知，不要求重新编辑稿件；提交前任何操作必须使用新鲜观察。跨执行日、超过 60 分钟或页面变动导致观察失效时，新建检查运行、重新读取并沿用原业务账本，不能改时间续命。

旧状态缺少新字段时按既有正常模式解释，不自动变成历史验收。首轮创建新的历史验收 run，引用原任务和副本映射，不把旧 run 的日期或模式改掉。

## 2. 先解决 WPS 历史读取入口

第一项真实验证仅只读，不进入稿件编辑或同步：

1. 在 Docker 专用浏览器打开现有文档共享版，核对源码与仓库一致。
2. 寻找并验证平台可见、受支持的执行参数入口，实际传入目标业务日期。不得调用未验证的隐藏接口或更改共享源码中的默认日期来冒充传参。
3. 保存本次原始日志，核对目标日期、工作表、合并范围、全部预约行、头条、备注与说明；核对 `generated_at` 为真实执行时间。
4. 参数入口无法使用就明确停在 `historical_parameter_ui_not_configured`，不返回无预约、不读取默认当天后改日期。

若现有网页确实没有受支持参数入口，备选为**另建文档共享的历史只读读取器**：一次运行有界读取全部日期块并输出原始数据，本地按显式业务日期选择唯一块。不得硬编码某一天、写入预约单元格、覆盖日常共享版或启用冻结个人版。该备选需要单独实现、部署与源码核对，并验证扫描配额、输出分块、超限失败和日期唯一性；实现困难或数据不完整时仍停止。先验证参数路线，再确定是否采用备选，不把备选当作已证明可行。

## 3. 稿件匹配和既有副本

保持使用**实际检查当天向前 14 个自然日**的稿件窗口，不因历史日期自动扩大范围，也不把首次发现时间当作转存时间。报告记录窗口起止和依据。已知旧副本可按账本定位作恢复核查，但不能替代来源稿件的当前核验；需要更早来源稿件时按既有规则另有明确依据才处理。

同稿判断、正文取证、标题差异提醒、错误周次和版本歧义等规则与正常模式相同。全部收齐并明确排序后才开始整组整理。

副本映射继续按账号、**业务日期**和源稿 ID 复用。历史模式不能建立一套绕过生产防重的新账本。已有 verified 副本重新观察并核对来源和保存结果，满足当前证据后跳过编辑；未完成副本先观察真实服务器状态。未知保存或修改结果不能因换 run、重启浏览器或缺少 repair_intent 就重放。

2026-10-13 的首轮预计复用第一、第二篇已有副本，第三篇按实际账本状态处理；准确篇目、ID和旧超时结果只存私有任务书及证据。报告逐篇区分“本轮修改完成”和“复用已完成结果”。

## 4. 转存与通知防重

同步任务仍按目标账号和**业务日期**归属，源稿/副本跨 run 防重记录继续有效。不能把模式或执行日期加入去重键来允许历史内容重新转存。

- 开始前检查原同步任务、提交预留和账号转存登记。
- 没有提交记录才允许按已授权流程组合、核对顺序和封面，并提交一次。
- 已预留、已提交或未知结果只走已有恢复路径；不能重新提交，不自行 `--confirm`。
- 已成功组合只验证结果和未完成通知，不制造第二次提交。与当前预约组合不一致时停止，不覆盖原记录。
- 平台外人工转存不天然进入本机账本；有已转存信息或冲突时先核实，不因账本缺记录就断言从未转存。

所有通知开头明确“历史验收｜预约日期｜执行日期｜运行标识”，列出头条及预约行序，明确是否已整理、是否已转存和标题差异。缺稿、登录异常、无预约也发送实际结果；未知不是完成。

相同事件、同一恢复步骤复用通知回执；新检查可以发送新的检查结果，但不能借换文件名或无关文字重发待决消息。只有 accepted 算平台接受；收件人是否已读不由回执推断。

## 5. 日志和 Token 归集

每轮同时记录模式、业务日期、真实开始/结束时间、执行日期、版本及提示词哈希、原任务关联、各环结果、复用/新建副本数、提交次数、通知回执、人工介入数、证据体积和未完成项。

业务阶段时间与模型会话用量窗口分开：允许用量覆盖会话开始到收尾，而业务 RunLog 晚于会话开始。增加可审计的独立用量窗口及其依据、来源会话和逐调用标识，校验真实时间、run 关联、重复调用与跨 run 重复归集；不回写虚构业务起点，不删除当前时间保护，不把未知补零。无法可靠归属的调用保持 partial 并说明边界。

同时补齐“召回有候选但均被正文证据排除”的结构化缺稿出口，避免机器报告写身份未确定而通知写缺稿。必须基于本轮有效候选的逐项排除或可审计的范围排除证据，不能只凭标题没有关键词就宣称缺稿。

## 6. 实施顺序与验收

| 阶段 | 工作 | 放行条件 |
|---|---|---|
| A. 历史读表只读验证 | 验证 WPS 参数入口；必要时评估独立历史读取器 | 真实返回目标日期，全部预约与排序完整，日志新鲜；失败如实阻断 |
| B. 日期贯通与回归 | full_run、daily_run、检查、状态、通知、日志共享日期上下文 | 正常模式保持当天；历史字段贯通；日期或模式不能偷换 |
| C. 防重与异常回归 | 旧状态兼容、既有副本、提交恢复、缺稿出口、用量边界 | 过期/未知不重放；换 run 也不能重复提交；证据和报告一致 |
| D. Windows 预览 | 部署版本，核对容器桥，实时读取目标日期并匹配 | 收齐、顺序明确、现有账本可接续，无编辑/同步副作用 |
| E. Windows 后半段验收 | 固定提示词直接投递，同一 agent 完成副本至通知 | 零途中审批或救场，保存重开通过，首次提交恰好一次且明确成功，通知 accepted |

回归至少覆盖：普通模式拒绝历史日期、历史模式拒绝当天/未来、合法历史读取、默认当天不能混入、WPS 参数失败和日期不存在、旧截图/过期观察、跨日新检查、恢复业务日期或模式被篡改、正确副本复用、未知修改不重放、历史/正式运行共享转存防重、未知同步只恢复、历史通知格式与去重、全部候选排除后的缺稿、用量前置窗口和重复归集。

窗口、租约、配置签名和正文图片样式保护维持原规则。公开测试用脱敏结构，真实账号、稿件、日志、截图和凭据留私有目录。Mac 与 Windows 分别记录离线结果；WPS 和转存的真实能力不能由单测数量代替。

首轮交付：固定代码版本、日期模式参数说明、Windows 历史验收任务书、逐环报告和校验过的证据包。若因缺稿或未知结果停止，记为合法异常路径；若中途修改代码或人工救场，记为调试。后半段通过后，再选择稿件齐全的当天，以正常模式完成一次完整成功路径，之后安排三天常态运行。

## 本方案暂不做的事情

不修改线上共享脚本、Windows 安装或调度；不重跑任何历史组合、不清账本、不自动部署、不发送消息。本文件仅确定下一阶段实现和验证顺序。历史参数网页入口仍是第一个待实测项。
