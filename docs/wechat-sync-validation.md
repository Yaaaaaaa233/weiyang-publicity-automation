## 只读脚本检查

同日新增 `scripts/check_sync_composition.py`，读取浏览器 `inspect` 快照和私有的、人工确认过的预约计划。它按唯一头条置首、其他篇目保留来源行序生成预期顺序，再检查同步组合区域的完整标题、封面背景样式、唯一目标账号和留言/预览复选框。左侧稿件库不计入组合。

当前真实四篇组合的 18 项检查全部通过，预期行序为 7、6、8、9。计划中的已提交次数为 1，因此脚本返回退出码 2，保持禁止直接再次提交。该次数由执行者依据账本填写，脚本不自行查询平台同步历史，也不是强制的浏览器执行锁。

另在真实快照的内存副本上分别注入错序、缺封面和错误账号，三项均被拒绝；没有修改平台页面。9 项单元测试通过，覆盖头条提序、无关稿件、重复标题、未知复选框状态和既有提交阻断等情况。

先将计划保存在 `local/`，在已配置好的同步页面展开账号与选项菜单，再只读采集并检查；快照和报告使用新的文件名，不覆盖交接证据。

```sh
python3 scripts/browserctl.py inspect body sync-composition-001.json
python3 scripts/check_sync_composition.py artifacts/sync-composition-001.json --plan local/sync-plan.json --output artifacts/sync-preflight-001.json
```

宿主机需要 Python 3.9 或以上；Windows 将 `python3` 改为 `py`，本轮新字段与检查器尚未在 Windows 实测。退出码 0 仅表示组合检查通过且计划声明此前未提交，可进入人工提交审核；2 表示检查失败或此前已提交；1 表示输入或报告路径错误。检查器不会点击同步，不会访问公众号后台。

封面检查只证明对应组件存在非空 CSS 背景及非零尺寸，不能证明资源加载成功、内容正确或裁切比例合规。此检查也不能证明预约计划读取正确、同题稿件身份正确、公众号草稿已生成，不能将其作为端到端成功证明。
