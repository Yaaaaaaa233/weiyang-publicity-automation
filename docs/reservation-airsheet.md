# 早期探索记录：脚本令牌路线

日期：2026-10-04。状态：**离线验证 57 项通过；已在真实预约表上实跑成功（第四周）**。

本文件记录用金山文档 AirScript 脚本令牌替代「截图 + 视觉转录」读取预约表的方案。
脚本本体在 `airsheet/reservation_dump.js`，离线验证在 `airsheet/verify_reservation_dump.js`。

## 为什么走这条路

现有预约表页面把网格渲染在 `<canvas>` 里。2026-10-04 实测当时一次运行的页面快照：
852 个节点、4 个 canvas，但 `innerText` 只有 222 个字符，全是工具栏和 sheet 标签，
**一个单元格的文字都没有**。因此读取只能靠视觉，而视觉转录有精度上限——
同一份表当时转出的「未央体育 | 2026新赛季…」与实际稿件「未央体育丨2026集结令…」
在分隔符和标题上都不一致。

官方开放平台（`developer.kdocs.cn`）的 [WPS 表格「获取单元格选区数据」接口](https://developer.kdocs.cn/server/et/workbook-get-cells.html)
能直接给出 `cell_text`，但其[入驻要求](https://developer.kdocs.cn/isp/access/access-open-kdocs.html)
写明「企业产品主要服务于 B 端用户」「成熟的研发团队」，且服务商信息表把**营业执照**列为必填，
学生宣传组无法入驻。

AirScript 是同一平台的另一条通路：脚本跑在金山文档服务端，通过**脚本令牌**由外部 HTTP 触发，
只需**实名认证**，不需要营业执照。见 [脚本令牌简介](https://raw.githubusercontent.com/dsdd1733/api-kdocs/master/AirScript/AirScript-apitoken-instro.md)
与 [接口说明](https://raw.githubusercontent.com/dsdd1733/api-kdocs/master/AirScript/AirScript-apitoken-api.md)。

## 安装

1. 金山文档打开预约表（需要**编辑权限**）
2. 上方菜单 **效率 → 高级开发 → 「AirScript脚本编辑器」**
3. 把 `airsheet/reservation_dump.js` 全文粘贴进去
4. 先点编辑器里的「运行」做一次冒烟：日志区会打印
   `sheet=… rows=… blocks=… date_blocks=… scanned_to=…` 以及每个块的 `[date]`/`[text]` 行
5. 确认无误后保存脚本

## 生成令牌并调用

1. 在脚本编辑器**工具栏**点【脚本令牌】→ 勾「我已知晓」→【创建脚本令牌】
2. 首次需要**实名认证**，完成后复制令牌
   （令牌与用户绑定，每个用户仅一个；默认 **180 天**到期，可手动延期）
3. 在侧边栏对目标脚本点「更多」→ **复制 webhook 链接**，形如
   `https://www.kdocs.cn/api/v3/ide/file/{file_id}/script/{script_id}/sync_task`
   —— `file_id` 与 `script_id` 已拼在链接里，不必另行查找
4. 调用：

```sh
curl -X POST 'https://www.kdocs.cn/api/v3/ide/file/{file_id}/script/{script_id}/sync_task' \
  -H 'AirScript-Token: {token}' \
  -H 'Content-Type: application/json' \
  -d '{"Context":{"argv":{"mode":"dump"},"sheet_name":"第二周"}}'
```

返回里 `data.result` 是脚本 `return` 的 JSON 字符串，`data.logs` 是执行日志。
耗时较长的场景可用异步版 `.../task` 取 `task_id`，再 `GET /api/v3/script/task?task_id=…` 轮询。

令牌属个人凭据，放 `.env` 或本机私有目录，不写入仓库。

## 真实文档实测到的界面与结构（2026-10-04）

在微信内嵌浏览器的金山文档界面上直接观察，坐标经截图 OCR 与视觉核对。

**入口**：「效率」是顶部一级标签（`开始 | 插入 | 数据 | 公式 | 协作 | 视图 | 效率`）。
效率页的按钮行自左至右是：一键美化、文件瘦身、提取文字、智能扫描录入、导出为PDF、
导出为图片、导出为多维表格、自动化流程、**高级开发**、快捷键、**PY脚本**、拼写检查、校对。
- AirScript 在 **高级开发** 的下拉里，名字是 **「AirScript脚本编辑器」**；
  官方文档写作「AirScript编辑工具」，按原名在界面上找不到。同一下拉里还有「定时任务」。
- **PY脚本** 是另一条路线，对应 WPS 的 [Python 文档](https://airsheet.wps.cn/pydocs/introduction/summary.html)，
  与 AirScript 不是同一个东西。

**表格结构**（当前显示「第四周」工作表）：
- 第 1–2 行：合并的「说明」文字块（A 列），不是表头也不是篇目。
- 第 3 行：青色表头 `发布日期 | 发布单位 | …`。
- **第 4 行：示例行**，A 列写 `例：2024/12/5`。它的日期能被日期解析器识别出来，
  必须显式排除，否则会变成一个伪日期块（`2024-12-05`）。脚本已按此修正，见 `example_rows`。
- 第 8–10 行 `2026/10/5 周一`、第 17–19 行 `2026/10/6 周二` 是日期块：**A 列日期与星期
  同一合并单元格内分两行显示**。
- **真实日期格式是 `2026/10/5`**（非补零），`normDate` 已覆盖。
- 顶栏显示「离线编辑中」。文档处于离线编辑状态时云端脚本／令牌读到的不一定是最新版本，
  用脚本前应先确认已同步。

**另一条路：效率 → 自动化流程（2026-10-04 实测，已展开到列表底部）。**

面板含模板分类 全部模板／企业微信／钉钉／表格／快递／数据库／飞书，模板有
「表格变更时发送企微群消息」「定时发送企微群消息」「表格变更时发送钉钉群消息」
「定时发送钉钉群消息」「定时导入MySQL数据」「定时导入钉钉表格数据」等，另有「创建空白流程」。

点开「创建空白流程」后的完整能力：

- **触发条件**：修改表格时 ／ 定时触发 ／ 手动触发
- **可执行操作**（已滚动到列表末尾，两次截图 sha256 相同确认到底）：
  - 推荐操作：发送企业微信群聊消息、发送钉钉群聊消息、查询SQLServer数据库、发送邮件消息
  - 分支：条件分支　｜　延迟：延迟
  - 执行脚本：**执行AirScript脚本**
- **没有任何 Webhook / HTTP 请求动作**，也没有通用 API 调用。

所以此事**不能**直接 POST 到我们已有的企业微信 webhook —— 它只能往群里发消息，
而群机器人只发不收，agent 读不到。

**但它解决了一个更难的问题：调度。** 「定时触发 → 执行AirScript脚本」意味着
AirScript 可以在平台内按时自动运行，**不需要脚本令牌，因而大概率也不需要实名认证**
（实名认证是脚本令牌这一外部凭证的要求，见 apitoken 文档原文）。这条尚未验证。

于是唯一剩下的缺口是「脚本怎么把结果交给 agent」。AirScript 自带
[网络 API](https://raw.githubusercontent.com/dsdd1733/api-kdocs/master/AirScript/AirScript-advanced-http.md)
（`HTTP.post`，需在脚本编辑器【服务】菜单里添加），但它**只允许访问不带端口号的域名**，
所以本机 `127.0.0.1:PORT` 不行，需要一个公网域名。三条收口：

1. **公网接收端**（推荐）：本机跑一个小接收服务 + cloudflared/ngrok 隧道，AirScript 定时
   POST 当天篇目 → 落盘成本地 JSON → agent 读。全自动，无令牌、无实名认证。
2. **企业微信群**：只能当通知，不能当数据通道（agent 读不到）。
3. **邮件**：动作有「发送邮件消息」，脚本也有 SMTP API，agent 可读 Mail.app —— 可行但脏。

A 与 B 的关系：B（脚本令牌）是**外部拉取**，A（自动化流程）是**平台内定时执行**。
两者都需要能打开「AirScript脚本编辑器」写脚本；A 额外省掉令牌和实名认证，
但需要自建接收端。**先验证脚本编辑器可用性，再决定。**

## 参数（`Context.argv`）

| 参数 | 默认 | 说明 |
| --- | --- | --- |
| `mode` | `dump` | `dump` 整表导出；`day` 只导出某一天 |
| `date` | — | `mode=day` 时使用，`YYYY-MM-DD` |
| `sheet` | 平台传入的 `Context.sheet_name` | 工作表名，优先于平台值 |
| `year` | 运行年份 | A 列只写「9月21日」时补全年份 |
| `cols` | `[1,2,3,4,5,10]`（A,B,C,D,E,J） | 要读取的列号；A 列始终读取 |
| `max_rows` | `200` | 最多扫描行数，防止 `UsedRange` 因残留格式异常膨胀 |

## 输出

`ok`、`sheet`、`sheet_names`、`used_range`（含 `capped`）、`cols_read`、`mode`、
`row_count`、`block_count`、`date_block_count`、`blocks`、`date_blocks`、`rows`、
`day_found`、`day`、`notes`。

要点：

- `blocks[].kind` 为 `date` 或 `text`。**只有 `kind=date` 才是日期块**；表头等 A 列有字
  但解析不出日期的行是 `text`，不参与头条行和备注判断。
- A 列是合并单元格，仅块首有值。脚本据此前向填充：每行带 `date_raw`（原始显示文本）
  和 `date`（归一化结果）。`date_raw` 从不改写。
- 解析不出日期时 `date` 留空，并归为 `kind=text`，**不猜测**。
- 列宽过窄时 `.Text` 可能返回 `####`。此时 A 列另给 `a_value2` 与 `a_value2_iso`
  （Excel 1900 日期序列号换算），可交叉核对。
- 空行不进 `rows`，所以块的 `end_row` 是块内最后一个**有内容**的行。
- 全文只读：没有任何对 `Value2`/`Formula`/`Interior`/工作表名的赋值。验证脚本第 [8] 组
  会用正则扫描源码来守住这条。
- 脚本只返回原始数据，**不做排序**。头条置首、其余按行序的规则留在 `daily_check.py`，
  业务规则仍随仓库发布。
