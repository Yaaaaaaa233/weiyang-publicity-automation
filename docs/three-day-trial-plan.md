# 封装完善与 Windows 三天试运行方案

日期：2026-10-08。状态：方案待实施；尚未启动三天试运行。

## 目标与现状

完善可迁移的执行流程和日志，在 Windows 上完成一次临时自动化验收，再用 DSH 新会话连续运行三天，为 demo、成本评估和长期日志管理提供数据。

目前 Windows 有监督流程已完成预约读取、稿件匹配、副本保存重开、一次同步提交和企业微信通知；104 项测试通过。上一轮公众号草稿箱结果仍待使用者确认。组合选稿曾需临时恢复，Token 只有整个会话累计值，尚不具备无人值守验收和单轮成本评估条件。

## 实施顺序

| 阶段 | 主要工作 | 通过标准 |
| --- | --- | --- |
| 1. 完善封装并推送 | 修复可见卡片与隐藏卡片导致的选稿歧义；封装正文观察与身份核验接口、副本创建、格式处理、保存重开、组合和同步接续；处理长通知；统一日志与用量采集 | 相关测试通过；未知结果先核查；重复接续不重复建稿、通知或同步；文档更新并推送 GitHub |
| 2. Windows 部署准备 | 经 UU 更新项目；核对 Docker、专用浏览器登录、共享读取器、通知私有配置、调度入口、联网与电源条件；准备新会话交接材料 | 版本一致；预检通过；检查点可恢复；日志落盘；Windows 为唯一业务执行者 |
| 3. 临时自动化验收 | 在 Windows 设置一次临时触发，使用当天预约，完成收稿核验、基础整理、公众号草稿箱同步及结果通知 | 无需人工点击审批；流程到达有证据的终态；正文图片保持、顺序和封面正确；若需人工介入则不算通过，修复后重新验收 |
| 4. 三天常态试运行 | Windows DSH 新建标准模式会话，权限设为 Auto review；按交接材料运行，逐轮记录数据 | 连续三天都有真实结果与日志；可区分业务异常、执行失败、转存待确认和实际完成；形成成本与稳定性报告 |

临时触发时间、三天起止日期及每日触发时间在部署验收后确定，统一使用北京时间。新会话用于模拟 agent 交接和测量用量，不携带此前完整探索聊天；交接材料包含规则、版本、配置位置、当前任务及恢复方法。

## 每轮业务流程

预检并领取任务 → 实读当天 WPS 预约、头条及备注 → 核验秀米登录与近 14 个自然日候选 → 根据正文、部门、日期、周次和版本确认稿件 → 收齐后整理独立副本 → 保存重开核对正文、图片、头尾图、分隔符、间距及封面 → 头条置首，其余按预约行序组合 → 提交一次公众号草稿箱同步 → 发送企业微信结果 → 保存摘要、释放租约。

无预约也通知。登录异常单独报告，不当成无预约或缺稿。标题不同但有证据确认同稿时仅提醒、不阻断；缺稿、错周次或未解决版本歧义阻断整组整理。正文身份核验可以使用 agent，但必须通过固定接口留下结构化证据，不能只凭标题相似度。

转存无明确成功证据时，以“转存待确认”结束并提醒，由使用者核对公众号后台；不重复提交，不操作后台，不发布。上一轮待确认任务先由使用者核对，并沿用原账本确认。

## 日志与容量管理

以下为拟实现的格式和初始保留策略，三天试运行后按实际体积调整。

| 文件或记录 | 核心内容 | 保留策略 |
| --- | --- | --- |
| 每轮 `summary.json` | run_id、业务日期、实际时间、电脑、版本、各阶段状态、篇数、耗时、重试、人工介入、Token、日志体积、证据索引 | 长期保留精简摘要 |
| 每轮 `events.jsonl` | 步骤开始结束、错误类别、恢复与验收结果；追加写入，接续沿用 run_id | 90 天，结束后可压缩 |
| 每轮 `usage.jsonl` | 调用时间、模型、请求 ID、普通输入/缓存输入/输出 Token、用量来源、费用依据 | 90 天；汇总长期保留 |
| 私有证据 | 正文基线、图片清单、关键截图、页面快照与回执 | 正常 14 天，异常 90 天；未解决任务暂不清理 |
| 去重与任务账本 | 源稿/副本映射、同步提交次数、通知去重及任务所有权 | 独立保留，不随普通日志清理 |

证据按内容哈希去重，默认仅保存关键验收点；出错时保存前后状态。日志按日期和运行标识分目录，轮转、压缩并清理到期文件。实施时配置总容量上限；空间不足时提醒并停止新增大证据，不能删掉未完成任务所需证据。所有凭据、Cookie 和登录数据排除，稿件与运行日志仅放私有目录，不提交公开仓库。

用量必须按运行时间边界和真实调用记录归集。恢复属于同一 run_id，新每日执行使用新 run_id；相同请求记录去重。费用根据真实模型及当期价格计算，不能直接把缓存输入与普通输入相加计费。DSH 无法提供某字段时记为未知；会话界面累计值不算单轮用量。部署、调试和日常执行分别统计。

## 无人值守边界与交付

Auto review 不保证所有动作获批；保持审查机制，通过固定、范围明确的操作和预检减少审批阻断。扫码、验证码、协议或新增授权仍由使用者处理。因审批中断的临时验收不记为通过；常态运行发生此类问题时记录并提醒。

交付：更新并推送的仓库、Windows 部署与新会话交接说明、一次临时自动化验收报告、三天日志和用量汇总，以及 demo 素材、成本评估和长期保留建议。三天中无预约、缺稿等业务结果不等于执行失败；但若未出现可整理转存的预约，不宣称三天覆盖了全部成功流程。
