日期：2026-10-02，匹配进度更新于 2026-10-03。状态：已完成真实四篇历史稿件的候选匹配；两篇明确候选，一篇周次差异，一篇存在两个排版版本。整组基础格式整理尚未执行，见[稿件匹配验证](draft-matching-validation.md)。

## 业务范围

常用秀米账号接收各组织稿件；依据每日推送安排表确认篇目、头条、顺序和备注，再整理基础格式。使用者不需要提供另一个来源账号，也不需要向其他秀米账号转存。2026-10-01 的合成稿跨账号实验作为接收能力证据保留，不是日常流程的必经测试。2026-10-04 明确后续需要从秀米组合多图文并同步到公众号草稿箱；公众号后台由使用者检查，agent 不操作后台、不群发。

以使用者提供或指定的当日安排表版本和明确调整为准。历史规范中的预约表截图、旧日期或旧地址不能自动作为当前任务输入。催稿、审核沟通、群内转发和最终发布仍由人工负责。

## 首轮输入

- 一天的安排表记录：日期、预期篇目、组织、头条标识、顺序、备注。
- 该组已经收到的稿件入口；只打开本次范围内的稿件。
- 当日明确的顺序调整，以及现行排版要求。没有实际调整时按安排表顺序。
- 基础格式测试使用独立副本；创建并核对副本后再修改。

第一轮优先选含多篇推送、头条和非头条的一天，以覆盖顺序核对。一篇复杂稿件只能验证其中的单篇格式能力。

## 执行及证据

1. 读取指定日期及完整相关列，建立当天有序任务清单，记录表版本、头条、备注及已提供的顺序调整。安排表与明确调整矛盾时待人工确认，不自行决定优先级。
2. 对应已接收稿件，输出已匹配、未收到、重复或身份不明确、安排外稿件状态。标题相近或同稿多版本不能自动任选；未收到只列待办，不自动催稿。
3. 对已匹配稿件建立检查基线：标题、段落、内容图片、装饰、封面、头尾图、落款和必要预览证据。保存原始定位与版本，创建测试副本并确认独立定位。
4. 在副本上按已确定规则整理标题和落款分隔符、头尾图、指定空行及封面。记录每项前后差异，不为测试随意改正文、添加作者或摘要。
5. 保存后从稿件库重新打开并明确刷新，核对基础格式确实保存，正文、内容图片和原有组件没有意外改变。读取被截断或图片未加载时先补足观察，不能判定通过。
6. 按当天预期顺序输出稿件定位与逐篇结果，包括头条、格式状态、异常和人工待办。缺稿或关键歧义不能标成整组准备完成；原有问题与操作引入的问题分开记录。
7. 写入持久化任务检查点、证据及下一步，完成或中断时释放执行者租约，供接续读取。

秀米稿件库的展示顺序不等于公众号多篇推送顺序。2026-10-04 使用者确认：当日标记的头条放第一，其余稿件保持预约表从上到下的相对顺序，在秀米“同步多图文到公众号”页按这一顺序组合。同步后的实际公众号草稿由使用者核对；秀米成功提示与公众号内容验收分别记录。多个头条、头条标记缺失或明确顺序调整冲突时报告异常，不自行选择头条。

## 基础格式依据及待确认事项

已只读核对本机《团委宣传组推送审核&发布注意事项》第 1–3 页。当前将其作为规则候选，以使用者的现行要求为准：

- 标题和落款的分隔符使用汉字“丨”，前后不加空格；不无差别替换正文符号。
- 检查头尾图，缺少时使用确认的素材；正文组件的组间距根据实际排版检查，不对整篇统一设为零。
- 规范第 3 页指定缺少的头尾图到“我的图库 → 头尾图”查找，并要求头图去掉组前后距。2026-10-04 已在本账号找到两张 GIF 并通过合成稿补齐验证；复杂组件中的间距调整另行观察。
- 落款到尾图之间及尾图后的空行需要检查；不删除整篇所有空段落。
- 原稿摘要、作者或原文链接为空且没有要求时，不强制补填。
- 落款中的审核信息按现行规范核对；身份和姓名不凭模型记忆改写。
- 封面要求区分头条与非头条。文件第 1 页写头条 3.35:1，第 3 页写 2.35:1 大封面及 1:1 小封面；现行比例未确认前只报告差异，不自动裁切或把任何一个数字定为通过标准。

## 验收标准

- 当天篇目、头条、备注、顺序均可追溯到输入版本。
- 每条安排对应正确稿件；未收到、重复、多版本及顺序冲突明确列出。
- 约定的基础格式改动保存并刷新核对；其他正文及素材保持预期内容。
- 无歧义且全部所需稿件通过后，才能标记“本轮基础整理完成”；该状态不表示已审核或可正式发送。
- 报告、稿件定位、截图、安排表内容及任务数据保存在 Git 忽略的本机目录，公开仓库只保存通用工具和脱敏规则。

可在本机虚构输入中验证缺稿、重复和顺序调整的处理，不通过改动真实安排表制造异常。真实整组验收完成后再安排中断恢复、换 agent、跨电脑和定时触发测试。
