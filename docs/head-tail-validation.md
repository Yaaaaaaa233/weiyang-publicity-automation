## 操作方法与观察要求

1. 核对已存在的测试稿件身份、首尾内容、图片和正文基线。只修正明确缺失或指定替换的位置。
2. 打开“我的图库 → 头尾图”，核对文件名、视觉内容与原始图片。图库缩略图含缩放参数，本次按 URL 主机和路径核对插入来源，未进行素材文件字节哈希比对。
3. 选中第一个正文组件，使用工具栏“前插空行”建立首部锚点，再选择图库头图。本次图库在空锚点之前插入图片，锚点仍存在；确认该组件确实为空后，通过组件工具栏删除。
4. 选中头图，在“组件定位”将组前距、组后距设为 0，并失焦核对。此设置符合规范的头图要求；复杂嵌套布局的间距尚未验证。
5. 本次尾部是明确的测试图片占位。选中它后点击图库尾图，平台替换所选图片，未增加重复尾图。缺少尾图、选中其他组件或复杂组合时不能假定动作相同，需要重新观察插入位置。
6. 保存、重开、刷新，等待文章预览稳定，再核对首尾素材、加载状态、间距、空段和正文保留。

GIF 某些帧近乎空白，单张截图不能判断头图缺失。编辑器首次重开可能处于宽度过渡阶段；本轮曾读到不同宽度，待页面稳定后重新读取，最终与原正文宽高一致。每次结构变化后重新读取选择器；旧 DOM 路径或旧坐标不作为下一次操作的可靠定位。

切换真实副本时，旧合成稿预览层仍留在页面中，而底层编辑器已切换。两张早期截图因此不能作为真实副本的视觉证据。已刷新清除旧层，重新读取副本并确认定位、正文及 16 张图片一致，取得正确编辑器截图。验收必须同时核对稿件身份与实际观察区域，不能只凭当前地址判断弹窗内容。

## 接续边界

本轮证明人工监督下可以用项目浏览器命令工具找到图库素材、补齐并保存回读。尚未实现自动遍历稿件的头尾图修复器，也未验证复杂组件布局、本轮业务操作的 Windows 行为或无人值守循环。
