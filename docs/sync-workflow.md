# 同步组合脚本

`scripts/sync_workflow.py` 将已确认的预约计划变成秀米多篇组合，复用专用 Docker 浏览器和 SQLite 任务账本。只通过浏览器可见 DOM 和标准 WebDriver 操作，不调用隐藏接口，不访问公众号后台。

这版覆盖稿件组合与提交记录。预约表画布的读取、同题版本选择、复杂正文基础格式整理仍由 agent 或人工处理；它不是完整的无人值守业务程序。

## 准备输入

复制 `fixtures/sync-plan.example.json` 到 Git 忽略的 `local/`，填写实际日期、在同步页观察到的完整地址、唯一目标账号显示名称和各篇完整标题。示例的地址是占位符，不能直接运行。

- `row`：预约表原始行号，不能用组合后的位置替代。
- `is_headline`：明确的布尔值，整组必须恰有一篇头条。
- `source_title`：确认过的秀米稿件库完整标题；同题多版须先确认版本并建立可区分的副本。
- `sync_title`：预期同步标题；可以与来源一致，测试时可显式加标记，脚本只改组合中的标题。
- `prior_sync_attempts`：此前同账号同日期组合已提交或结果未知的次数。不能因为换电脑或换运行目录而归零。
- `plan_confirmed`：计划与稿件选择已经核对的记录，不是平台授权，也不能代替使用者对业务操作的授权。

原有封面、作者、链接和正文沿用选入稿件的内容。本版不会补封面、裁切封面、修复正文或填入审核姓名。缺封面样式、选项异常、账号歧义均停下报告。

## 运行

先启动 Docker，并由使用者在独立浏览器完成人工登录和已有账号授权。宿主机需要 Python 3.9 或以上，Windows PowerShell 将 `python3` 改成 `py`。

```sh
python3 scripts/sync_workflow.py prepare local/sync-plan.json --run daily-example
```

`prepare` 新开独立页面，保留旧窗口，确认目标账号后按“头条第一，其余保持源表行序”选入。搜索入口折叠时展开；完整标题找不到时用标题栏目或明确测试标记做短关键词检索，仍要求完整标题唯一匹配，绝不任选第一条。只对读取与搜索做有界等待，选入和输入失败时不自动重放。

组合完成后核对完整标题、封面样式、目标账号、留言和预览选项，生成私有报告并停在 `prepared`，不提交。界面控件被改版、加载超时、重复标题或来源缺失时保留证据，状态为 `needs_manual`。

在取得本次提交的业务授权并检查组合后，使用明确执行命令：

```sh
python3 scripts/sync_workflow.py submit --run daily-example --execute
```

提交前再次读取实际组合并检查。仅当此前未提交、任务准备完成时，将 `submission_intent` 和次数 1 提交到 SQLite，再点击一次“开始同步”。即使按钮调用失败、进程中断或后续结果不明确，也不自动归零或再次点击。该保守顺序可能在“记账后、点击前”中断时需要人工核对，但不会把未知结果当成尚未提交。

当前提交模式只记录初始观察并进入 `awaiting_confirmation`，不把进度消失认定为成功。公众号草稿由使用者检查，随后记录实际结果：

```sh
python3 scripts/sync_workflow.py confirm --run daily-example --result ok --note '使用者已在公众号草稿箱核对内容、顺序和封面'
python3 scripts/sync_workflow.py confirm --run daily-example --result problem --note '记录实际发现的问题'
```

上面两条是互斥结果的示例，实际只运行对应的一条。`ok` 完成任务；`problem` 保留人工处理状态及已提交次数，也不提供自动重试。`confirm` 不打开浏览器或公众号后台。终端只显示阶段、计数和任务 ID，稿件与动作细节留在私有目录。

## 中断、换 agent 和换电脑

同一浏览器会话接续：

```sh
python3 scripts/sync_workflow.py inspect --run daily-example
python3 scripts/sync_workflow.py prepare local/sync-plan.json --run daily-example --resume
```

接续会核对已经选入的完整标题前缀，仅补剩余篇目；不会清空不认识的组合。若在选入后、改组合标题前中断，只接受最后一篇的明确来源标题或预期同步标题；空标题或其他值停下人工恢复。已经预留同步的任务不允许重新组合。

每次动作前后记录检查点，结束时释放任务租约，导出带证据 SHA256 的交接 JSON；路径写在 `local/sync-workflow/<run>/state.json`。证据沿检查点累积，不覆盖旧文件。同账号同日期只登记一组，改运行目录名、改同步标题都不能绕过已有任务；当前不提供同一天新建第二组或自动改计划的路径。

换 agent 可读取相同本机数据。换电脑时停止旧执行者，复制本次源码、对应 `local/sync-workflow/<run>/` 和交接引用的全部私有证据，再将释放租约的交接 JSON 导入目标账本（见 `docs/tasks.md`）。浏览器登录另行配置；只克隆 Git 不会复制任务和登录。

窗口 ID 跨会话会失效。使用者或 agent 在新浏览器打开实际同步页后，明确关联当前窗口：

```sh
python3 scripts/sync_workflow.py attach --run daily-example --current-window
```

`attach` 核对账号和已选标题前缀，再记录新窗口定位。尚未提交的任务随后运行 `prepare --resume`；已提交的任务继续核验结果，次数保留，不能重发。用户确认结果可以直接 `confirm`，无需恢复旧窗口。

本机 `data/sync-workflow.lock` 防止此工作流同时运行，SQLite 租约保护任务写入，浏览器另有单命令锁。它们不能阻止其他脚本或人工操作浏览器，也不能跨两台独立机器强制协调，因此只运行一个执行节点。进程被强制终止后工作流锁会保留；先确认原进程已停止、平台实际状态及租约，再人工清理该锁，不能自动删锁接管。

## 当前验证

2026-10-04，Mac 已在独立秀米页面实际运行 `prepare`，自动选入历史四篇、调整组合头条测试标题，18 项检查通过。此前这组实际转存已获使用者内容验收；本次自动组合测试保留已提交次数 1，没有再次同步。`attach` 重新关联窗口及同页 `prepare --resume` 已实际通过，完整前缀不重复选入。

26 项离线测试通过，覆盖提交预留、按钮调用失败后不重放、已有次数、任务重复、唯一匹配、折叠搜索和断点选择。真实页面还验证了错误文本点击、歧义控件点击以及缺少执行标志均被拒绝；自动组合的四个封面来源与此前用户验收组合一致。Windows 新脚本尚未实测，不能将旧的环境迁移测试写成本工作流通过。封面仅检查非空背景样式和尺寸，加载、内容、裁切比例仍需视觉验收。

## 自动提交首次实测与选择器脆弱性

2026-10-04 在 9-21 历史预约上完成本工作流首次真实 `submit`：`prepare` 自动选入三篇（行序 7、6、8），16 项组合检查通过，`submit --execute` 点击一次「开始同步」，进度层出现到 6% 后消失并返回组合界面，未捕获明确的成功或失败提示，状态进入 `awaiting_confirmation`。使用者在公众号草稿箱核对内容、顺序和封面无误后 `confirm --result ok`，任务 `569eb0ac814040208f106e5ed235dc3a` 记为 `completed`、版本 26、已提交次数 1。该结论来自使用者核验，不是脚本推断的同步成功。

同一轮暴露一个尚未修复的缺陷：脚本沿用快照中的绝对 `nth-of-type` 路径作为选择器，而秀米 `#/wxpack` 页在渲染过程中会增删顶层 `div`，使 `body > div:nth-of-type(N)` 及其后续链路失效。实测该选择器在失败时刻匹配 0 个元素（同页 `input[placeholder="输入关键词后按回车键"]` 稳定唯一）。两次失败分别表现为 `ambiguous focus`（搜索框）和 `ambiguous click`（点击元素），均由 `prepare --resume` 核对已选前缀后补齐剩余篇目恢复，没有重放任何有副作用的动作。修复方向是动作时重新解析元素或改用属性选择器，尚未实施，也未补充对应测试。
