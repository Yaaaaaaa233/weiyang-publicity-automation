# Windows 部署准备与验收清单

第二阶段只更新与预检，不创建业务副本、提交公众号同步、发送新通知或启用三天调度。历史待确认任务继续保留，不作为新任务重放。

## 更新与恢复

1. 使用确定提交的 Git 源码归档，核对完整提交号、ZIP SHA256 和逐文件哈希。备份更新前源码；更新仅涉及版本控制文件，私有配置、浏览器卷、任务账本和去重回执保持。
2. 核对宿主机源码及容器实际执行的 `browser.py`。不能只验证源码目录而忽略容器可写层；重建时须使用本机已验证的镜像构建方式，保留浏览器卷。
3. 执行 Python 测试和 AirScript 离线验证。结果记录平台、解释器版本、命令、退出码和实际测试数。
4. 更新中断后先比对目标文件及备份，不能重复覆盖未知状态；不删除 Chromium 配置或历史业务账本。

## 实际预检

- 当前无其他活跃业务执行者；账本与浏览器租约可正常领取释放。
- Docker Desktop 与专用浏览器可启动；Windows 独立登录 WPS 和常用秀米账号，不能以 Mac 登录代替。
- WPS 共享读取器源码与仓库逐字一致；冻结个人版不运行。当天只读预览使用新 run_id，记录真实读取时间及结果。
- 企业微信配置在本机 `.env` 与私有群状态中；只核对键存在、目标群与已有回执，不输出 Webhook。
- `local/full-config.json` 使用实际账号、预约地址、已审核业务说明指纹与公众号目标；头尾图规则对应实际观察及本机证据路径，不能使用示例占位值。
- 本机日志能落盘，剩余磁盘空间和 5 GiB 采集上限有余量；有明确恢复路径。电脑接通电源、联网，检查接电休眠与合盖行为；保持认证和审批保护。
- DSH 调度入口须从实际界面或本机实现核对，确认时区、触发条件、工作目录及权限模式；第二阶段仅准备交接和停用的配置，不开始正式运行。

## 新会话交接模板

工作目录：Windows 实际项目路径。先读 AGENTS.md、docs/full-runner.md、docs/run-logging.md、docs/draft-matching-validation.md 和本机部署检查点。

使用标准模式、Auto review。本机为唯一业务执行者；开启运行前再次观察锁、登录和当天日期。正常当天执行使用稳定的新 run_id，恢复沿用原 ID。默认入口只预览；具备当天完整流程授权后使用 `full_run.py --execute`，按返回的 identity_request 和 format_request 提供真实正文证据和修复动作。同次未知创建、通知或同步不重放；同步仅提交一次，待确认如实报告。公众号后台与发布由使用者操作。

不携带探索聊天正文、密钥或旧截图作为当前证据。交接文件只提供本机配置路径、待确认任务定位、恢复命令与验证状态。

## 用量和阶段通过条件

DSH 实际日志必须具备可核对的调用身份与运行边界。只导出请求标识、模型、调用时间和用量字段；不导出聊天正文。重复存储按真实请求身份去重，不能按相邻数值相同猜测。若缺字段或边界不能证实，记录未知并阻止将其用于单轮成本结论。

部署通过须有 Windows 的版本与测试证据、实时只读预检、正确私有配置、日志与调度交接。它不等于无审批完整流程通过；后一项只能在第三阶段真实临时触发验收。三天日期和时间在此后确定。
